# 製令製程明細表（SFCR06）

> 何時要讀這份文件：修改 `/api/sfcr06/list`（app.py）或管理頁「製程明細表(SFCR06)」子頁時。

## 背景

使用者想要的資料對應 ERP 原生畫面「製令製程明細表(SFCR06)」（鼎新/Computech ERP 內建報表，不是我們現有的 SSRS 自訂報表，SSRS 報表伺服器上查不到）。資料改成直連 `192.168.1.140` 的 `YC01` SQL Server（沿用 `get_erp_conn()`，跟 BOM/途程查詢同一套連線）。

## 資料表：SFCTA（製令途程交易檔）

`SFCTA` 是**製程層級**表（一個製令底下每個加工順序各一列），381 萬+ 列，欄位是 Computech 慣例的 `TA001`~`TA092` 無說明代碼。以下欄位是用使用者提供的真實 SFCR06 匯出資料逐欄比對驗證過的（不是猜測）：

| SFCTA 欄位 | 對應意義 | 驗證方式 |
|---|---|---|
| TA001 + TA002 | 製令單號（單別+序號） | `5166`+`20250217025` |
| TA003 | 加工順序 | `0010` |
| TA004 | 製程代號 | `J01` |
| TA005 | 性質（`1`=廠內製程／`2`=外包） | 外包列會對應到 TA007='鍾冶'/'遠利' 等廠商名 |
| TA006 | 線別/廠商代號 | `000-2` |
| TA007 | 線別/廠商名稱 | `成品部` |
| TA008 | 製程開工日（YYYYMMDD） | `20260127`→`2026/1/27` |
| TA009 | 製程完工日 | `20260204`→`2026/2/4` |
| TA010 | 投入數量 | `1375.000` |
| TA011 | 完成數量（只有該製程已完工才有值） | `1378.000` |
| TA022 | 標準人時（**單位是秒**） | `2750`秒 = `0:45:50`，跟報表欄位完全吻合 |
| TA023 | 標準機時（單位是秒，信心稍低但格式吻合） | `600`秒 = `0:10:00` |
| TA024 | 製程敘述/規格說明文字 | `1.T20圓刀螺絲 2.染黑 3.散裝` |
| TA030 | 實際開工日 | `20260127` |
| TA031 | 實際完工日（只有 TA032='Y' 才有值） | `20260202`→`2026/2/2` |
| TA032 | 完工碼（`Y`/`N`） | `Y` |

製程代號→製程名稱用 `LEFT JOIN CMSMW w ON RTRIM(w.MW001)=RTRIM(a.TA004)`（`MW002`=製程名稱），跟既有 `/routing` 產品途程查詢用的同一張代碼檔，不是另外新猜的。

## 產品品號/品名怎麼補

SFCTA 本身**沒有**品號/品名欄位。分兩段補：

1. 優先查既有的 `fetch_all_unfinished('all')`（製令查詢主頁同一套快取資料），用 `單別` 欄位（裡面其實放的是完整製令號，如 `5188-20260521009`）對應 `品號`/`品名`/`製令預計開工日`/`預計生產數`。
2. 上面查不到的（通常是已完工、不在「未完工」清單裡的舊製令），改查 `SFCTC`（移轉單明細）：`SELECT TOP 1 TC047, TC048 FROM SFCTC WHERE TC004=? AND TC005=?`（TC047=品號、TC048=品名，品名尾巴有 `||` 要去掉）。

第 2 段是逐筆查 ERP（N+1 query），日期範圍太寬時可能變慢，所以設了 500 筆上限（`missing_oids` 超過就不再補，那幾筆品號/品名留空）。實測：5 天範圍、373 筆需要 fallback 查詢，約 3.9 秒；同範圍若大多數訂單還在「未完工」清單命中第 1 段，可以快到 0.5 秒內。**日期範圍開太寬（例如整年）會明顯變慢，建議搭配關鍵字縮小範圍。**

## 預計完工日（製令層級）算法

`SFCTA` 沒有「製令的整體預計完工日」這種單一欄位（只有逐製程的 TA009）。做法是同一個製令底下取所有列 `製程完工日`（TA009）的最大值，當作這張製令的「預計完工日」——也就是最後一道製程完工，整張製令才算完工的概念。

## 已知限制

- 已完工很久的舊製令查不到「預計開工日」「預計產量」（因為這兩個欄位只從「未完工製令清單」補，舊製令早就不在那份清單裡了；`SFCTC` fallback 只補品號/品名，沒有補這兩個欄位）。
- `TA023`=標準機時的信心不如 TA022（標準人時）高，只用格式吻合來推論，沒有逐筆比對到第二筆驗證資料。
- 預設查詢範圍是當月（`製程完工日` TA009），避免一次掃過 381 萬列；前端日期欄位留空+有關鍵字時才會查全部時間範圍。
