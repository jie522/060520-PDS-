# PDM 治檢具申請單自動化 — 作業標準（可複用範本）

> 何時要讀這份文件：想比照治檢具申請單的做法，用其他帳號、對其他 PDM 申請單類型（如
> 設計變更申請、模具採購單、SOP 需求申請單…）做同樣的「GUI 自動建單」功能時。
> 這份文件是把 `app.py` 裡 `jig_apply*` 三支 API 的實作經驗抽成通用步驟；
> API 底層行為與陷阱的詳細出處見 `docs/pdm-api-cookbook.md`，本文件不重複，只講「怎麼複製這個模式」。

## 一、整體連接流程（四層資料流）

```
使用者填表單（PDS 網頁）
   │  POST /api/xxx/apply
   ▼
Flask 後端（app.py）─┬─ PDM COM API（win32com，LoginAuto 免帳密）
                     │      → 配號、建資料夾、寫資料卡變數、控制簽入/取出、變更流程狀態
                     └─ openpyxl（本機檔案）
                            → 改 Excel 儲存格值、貼示意圖，寫完後把 PDM 卡片格式還原回去
```

**建單的標準 6 步驟**（對照 `jig_apply()` 實作）：

1. **配號**：`IEdmSerNoGen7.AllocSerNoValue(序號產生器名稱)` 取得單號（跟人工在檔案總管建立用同一個計數器，不會撞號）
2. **建資料夾**：在指定 vault 路徑下 `AddFolder(0, 單號, None)`
3. **寫資料夾卡片變數**：`SetVar` 逐欄寫入 → `Flush`
4. **建標準子資料夾**（如果該類型有固定子資料夾結構）
5. **複製空白 Excel 範本 → 改寫 → 加入 PDM → 走完工作流程分派 → 取出給使用者**（見下節「Excel 申請單建立」，這是全流程最容易出錯的一段）
6. 回傳單號與資料夾路徑給前端

## 二、換帳號時要做的事

`_pdm_vault_login()` 用的是 `vault.LoginAuto(VAULT_NAME, 0)`——**沿用本機已登入的 PDM 用戶端工作階段**，不在程式碼裡存帳密。換帳號的意思是：

- **同一台電腦、換人用**：請該使用者自己在 PDM 用戶端（檔案總管外掛）登入他自己的帳號，之後這支程式會自動用「當下登入者」的身份操作。**不用改程式碼**。
- **要在程式裡指定成特定帳號**（不論當下電腦登入的是誰）：`LoginAuto` 不支援這樣做，要改用 `vault.Login(帳號, 密碼, VAULT_NAME)`，但這樣就必須在 config.py 或環境變數存密碼——**先確認是否真的需要**，多數情況「跟著使用者身份走」才是對的（權限、簽核紀錄都要是操作者本人）。
- **申請人欄位**：目前是讀 `IEdmUserMgr5.GetLoggedInUser()` 再 cast 成 `IEdmUser6` 取 `FullName`，會自動對應到當下登入的帳號，換人用不用改。

## 三、PDM 端要先確認的四件事（動手寫程式前）

比照治檢具申請單的做法套到新類型時，先用**唯讀**方式確認以下四件事，缺一個都會卡關：

| 要確認的事 | 怎麼查 | 治檢具的實際值（範例） |
|---|---|---|
| 序號產生器名稱 | `IEdmSerNoGen7.GetSerialNumberNames()` 列出全部，比對檔案總管新增精靈跳出的號碼格式 | `PT_PT專案序號(2026後)` |
| 空白 Excel 範本路徑 | 問使用者「新增精靈用的範本檔存在哪」，通常在 `vault 路徑\00-空白範本\` | `C:\MAXCLAW\06-生技課\00-空白範本\PP-M-041機器模檢治具申請單(2026後).xlsm` |
| 資料夾卡片變數名稱 | 開一個既有資料夾，`IEdmEnumeratorVariable5.GetVar()` 或直接在 PDM 資料卡介面看欄位名稱 | `PT_專案代號`／`PT選單`／`YC_機型`／`YC_品名`… |
| Excel 卡片變數名稱 | 讀範本 xlsm 的 `docProps/custom.xml`（見 cookbook），或 Excel 開啟後看「公式」→「名稱管理員」 | 同上，且多一個關鍵欄位 `00文件分類`（決定 workflow 分派結果，**必查**） |

`00文件分類`（或該類型對應的分類欄位）是整個流程裡最容易漏掉、也最容易讓申請單卡進錯誤狀態的欄位——**这是 workflow 自動分派的判斷依據，不是普通顯示欄位**，務必在寫程式前確認它的正確值（通常等於範本檔名，例如治檢具是 `機器模檢治具申請單(2026後)`）。

## 四、Excel 申請單建立的正確順序（最容易出錯的一段）

```
複製範本檔（本機暫存）
   → 改寫 docProps/custom.xml 卡片變數值
   → AddFile 加入 PDM（此時檔案「取出」給操作者，無 workflow 狀態）
   → 用 IEdmEnumeratorVariable5.SetVar(...,'') 把變數寫進「資料庫」（不是只寫 custom.xml）
   → Flush
   → UnlockFile 簽入 ← workflow 依「資料庫裡的分類欄位值」自動分派狀態，就在這一刻決定
   → 輪詢 CurrentState.Name，等到分派成你要的初始狀態（實測約 2 秒，最多等 10 秒）
   → 分派成功 → LockFile 取出還給使用者繼續填表
   → 分派失敗/逾時 → 不要重複簽入，寫警告訊息告知使用者，讓管理員介入
```

**為什麼要照這個順序、不能簡化：**
- AddFile 那一刻，Excel 檔案內的變數值（custom.xml）**不會**自動同步進 PDM 資料庫；workflow 分派只看資料庫值。跳過「SetVar 到資料庫」直接簽入，分派條件永遠不成立，會掉進「其他文件歸檔」之類的死路狀態（進去出不來，一般帳號沒有取出/刪除權限，只能求 PDM 管理員）。
- 剛剛才 AddFile 的檔案，如果**立刻**簽入再立刻對它 PATCH/PUT 寫入其他資料，也有機率被 PDM 忽略（本專案在另一個 Node.js 工具整合 ZUMEN 平台時，同一類「剛建立就寫入」的陷阱又踩了一次——**新建立的物件，凡是要再寫入資料，一律先等它經過一次完整的狀態轉換或短暫延遲，再讀回驗證**，這是通則不是治檢具專屬）。
- 每次寫入 PDM 資料庫或檔案後，**寫完不代表寫成功**——PDM/類 PDM 系統常見「回 200 / 不報錯，但實際沒寫入」，務必讀回比對再回報使用者成功。

## 五、GUI 介面設計（兩步式表單，複製這個模式）

參考 `templates/management.html` 的 `openJigApplyModal()` / `#jig-apply-modal`：

**步驟 1（基本資訊，觸發建單）**：機型/品號、品名、類型（下拉，選項從現有資料夾掃出來，不要寫死）、送出後呼叫建單 API。

**步驟 2（建單成功後，同一彈窗切換內容）**：
- 顯示剛配到的單號
- 主要欄位表單（緊急程度、性質、期望完成日…視類型而定）
- 特殊需求勾選框（對應 Excel 裡的 `■`/`□` 前綴欄位，勾選=`■`、未勾=`□`，注意前後空白要跟範本原始文字完全一致）
- 示意圖上傳（openpyxl 插入儲存格區域，記得等比縮放）、其他需求文字（openpyxl 寫儲存格＋自動換行＋依行數調列高）
- 兩個獨立勾選：「儲存後自動存回」「並提出申請（送審）」——**分開勾選讓使用者自己決定要不要送審**，不要綁死成同一個動作，各單位審核流程不同，需要彈性

**「提出申請」怎麼做**：找出該 workflow 從初始狀態出去的轉換名稱（用 `IEdmWorkflow6.GetFirstTransitionPosition` 列出 `FromState.Name`／`Name`／`ToState.Name`），呼叫 `f5.ChangeState(目標狀態名, folder.ID, 註解文字, 0, 0)`。治檢具的轉換是「00-提出申請」，目標狀態「單位主管審核」——**每種申請單的轉換名稱都不同，套用前務必用唯讀方式列出來確認**，不要憑治檢具的值去猜別種申請單的轉換名稱。

## 六、注意事項總清單（照抄會踩到的坑）

1. **gen_py 對 optional COM 參數的預設值是 `0`，傳下去會轉型失敗**——`AddFolder`、`GetFileFromPath` 等函式，第二/三個可省略參數要明確傳 `None`。
2. **卡片變數有三個存放處**：資料庫（`SetVar`+`Flush`，workflow 判斷用）、Excel 檔案本體（`CloseFile(True)` 才會寫入，取出中檔案的資料卡顯示這裡的值）、Excel 工作表儲存格（`openpyxl` 依 Defined Names 寫，跟前兩者完全獨立，其他索引工具若讀儲存格就必須也寫這裡）。三處都要寫，缺一個某個環節就會看起來「沒存到」。
3. **組態名稱一律用空字串 `''`**，不要用 `'@'`——`'@'` 會在 PDM 資料卡上多出一個空白組態分頁（實測過會發生，肉眼可見但無法用 API 清除，只能重建檔案）。
4. **一般帳號通常沒有刪除資料夾/檔案的權限**——寫入前想清楚，實驗盡量在唯讀操作或測試資料夾裡做，建錯了很難收拾，只能請 PDM 管理員清。
5. **openpyxl 存檔會動到 `docProps/custom.xml` 的序列化格式**（PDM 卡片變數的 `linkTarget` 屬性等）——用 openpyxl 改 Excel 內容（儲存格、插圖）前，先把 custom.xml 讀出備份，存檔後用 zipfile 把原始 custom.xml 塞回去，否則 PDM 卡片可能讀不到值。
6. **`import openpyxl` 第一次載入可能耗時二三十秒**（防毒掃描），不要誤判為程式卡死；真的懷疑卡住時用 `faulthandler.dump_traceback_later()` 看卡在哪一行，不要盲目重試。
7. **測試腳本一律寫成 UTF-8 檔案再執行**，不要用命令列 heredoc 直接塞中文字串——Windows 主控台編碼問題會讓中文變亂碼，傳給 COM API 也可能出錯。
8. **每個環節都要有失敗善後**：序號配了但後面失敗要 `Rollback()`；資料夾建了但 Excel 建立失敗，資料夾本身仍保留（不要整批復原，讓使用者知道「單號已產生，Excel 沒建成功，需要手動處理」比整個消失更容易追蹤）。

## 七、把這個模式套到新申請單類型的檢查清單

- [ ] 用第三節的方法查到：序號產生器名稱、範本檔路徑、資料夾卡片變數名稱、Excel 卡片變數名稱（含「文件分類」欄位）
- [ ] 唯讀方式列出該 workflow 的初始狀態、以及要用的轉換名稱／目標狀態名稱
- [ ] 確認該類型有沒有固定的子資料夾結構（沒有就跳過第四步）
- [ ] 比照 `jig_apply()` / `jig_apply_defaults()` / `jig_apply_card_save()` 寫三支 API，變數名稱換成新類型的
- [ ] 比照 `#jig-apply-modal` 寫兩步式前端表單，欄位/勾選框換成新類型的
- [ ] 先在**測試/唯讀**情境驗證整條流程（配號→rollback、讀卡片值），確認無誤才真的建立一筆測試資料
- [ ] 建一筆測試資料，人工到 PDM 資料夾核對：資料夾卡片、Excel 卡片、Excel 儲存格三處的值是否一致
- [ ] 確認「提出申請」轉換後的狀態，跟 PDM 管理員或該單位主管核對是否正確送到審核關卡
