# 批成本計算（batch_cost.html）

> 何時需要讀這份文件：修改批成本相關功能（`templates/batch_cost.html`、`app.py` 裡 `/api/batch_cost/*` 路由）時。

頂層導覽列「批成本」分頁（位於「產品途程查詢」與「管理」之間）。依製令計算單批的刀具耗用成本＋加工費用，左側選單分四個子頁：

- **批成本計算**：①輸入製令查詢（支援不打 `-`，純數字會自動補回 4位單位代碼+`-`+序號格式）→ 自動帶出品號/品名/製程代號/製程名稱/報工人員/加工秒數/機台名稱代號（依「製令+製程代號」比對 K1_P2 生產報工統計與生產日報表P5.3）→ ②填完成數量/每秒鐘生產費用 → ③自動帶出該品號刀表，沒有則可現場新增/編輯 → ④逐刀填使用次數即時試算成本 → ⑤確認送出。
- **批成本明細**：讀『批成本計算』分頁全部記錄，支援搜尋+月份篩選+刪除；每列可展開查看該批次每把刀的使用明細（依「建立日期+製令+製程代號+品號」比對『製令與刀具壽命』分頁，並 join『刀具資料』補項目/供應商）；明細列依「建立日期」由新到舊排序。內含「統計」分頁：柱狀+折線組合圖（SVG 動態疊加折線於柱狀圖上）+平均值虛線參考線，月份成本趨勢、依品名平均加工成本比較。
- **刀表維護／刀具資料維護**：對『刀表』『刀具資料』分頁的完整 CRUD（新增/編輯/刪除），不透過製令查詢流程也能直接維護。
- **設備耗用設定**：對『設備耗用設定』分頁（每台設備電流/電壓/每日耗油費用/每日工作時數）的完整 CRUD，加上一個「全域設定」小表單設定『批成本全域設定』分頁的每度電價（所有設備共用一個電價，不逐台設定）。這份設定驅動①批成本計算頁 Step4 試算表新增的「電費」「油費」兩行。新增/編輯時的「機台代號」是下拉選單（`/api/batch_cost/machine_list`，從『生產日報表P5.3』抓出現過的機台代號/機台名稱去重），且會排除已經設定過的機台代號（自己編輯中那筆例外），避免重複設定同一台。

資料來源是共用區一份 Excel 範本（`config.py` 的 `BATCH_COST_FILE_PATH`），固定 6 個分頁：

| 分頁 | 設定常數 | 內容 |
|------|------|------|
| 刀具資料 | `BATCH_COST_TOOL_SHEET` | 刀具名稱→單價/刃數/項目/供應商對照 |
| 刀表 | `BATCH_COST_TOOLMAP_SHEET` | 品號→T1~T39 刀具配置（不分製程代號） |
| 批成本計算 | `BATCH_COST_RECORD_SHEET` | 每筆計算結果（不存在時自動建立） |
| 製令與刀具壽命 | `BATCH_COST_LIFESPAN_SHEET` | 每筆計算對應的逐刀使用次數明細（不存在時自動建立） |
| 設備耗用設定 | `BATCH_COST_EQUIPMENT_SHEET` | 機台代號→平均電流(A)/電壓(V)/每日耗油費用(元)/每日工作時數（不存在時自動建立） |
| 批成本全域設定 | `BATCH_COST_GLOBAL_SHEET` | 單列，只有一個「每度電價」欄（不存在時自動建立） |

成本公式：
```
刀具耗用成本（單把） = (使用次數 × 單價) / 刃數
刀具成本（單位） = 刀具費用總計 / 完成數量
加工費用（單位） = (加工秒數 / 完成數量) × 每秒鐘生產費用
加工費用(含刀具成本) = 加工費用 + 刀具成本

每秒電費率 = 平均電流(A) × 電壓(V) ÷ 1000 (kW) × 每度電價 ÷ 3600
每秒油費率 = 每日耗油費用 ÷ (每日工作時數 × 3600)
電費（單位） = (加工秒數 / 完成數量) × 每秒電費率
油費（單位） = (加工秒數 / 完成數量) × 每秒油費率
總成本(含刀具+油電) = 加工費用(含刀具成本) + 電費 + 油費
```
電費/油費依 Step2 帶出的「機台代號」查『設備耗用設定』；查不到對應設定時兩者顯示 0 並提示去設定，不擋原本的送出流程（向下相容：舊資料/未設定的機台完全不受影響）。批成本明細頁的表格是依 API 回傳的 `columns` 動態產生欄位（見下方「實作慣例」），所以電費/油費/總成本(含刀具+油電) 這三個新欄位新增後會自動出現在明細表，不用額外改前端渲染邏輯。

**每秒鐘生產費用也改成放在『設備耗用設定』裡管理**（新增一個「每秒鐘生產費用(元)」欄位，跟電流/電壓/油費同一張表），批成本計算 Step2 不再讓使用者手動輸入，改成依機台代號自動查（查不到退回預設 0.2 元/秒，唯讀顯示，要調整去左側「設備耗用設定」頁改）；批成本明細表也不再顯示這欄。

**`/api/batch_cost/equipment/save` 會自我修復表頭**：程式後來才新增的欄位（例如「機台型號」）如果既有 Excel 檔案的『設備耗用設定』表頭裡還沒有，儲存時會自動把新欄位補到表頭最後一欄再寫值，不會動到既有欄位順序。這是因為「依表頭欄名動態對應」的舊寫法只會忽略表頭沒有的欄位、悄悄不寫入——對已經在正式檔案裡建過表的分頁（設備耗用設定一開機就有 5 台機器），這樣新欄位永遠存不進去。**之後任何會寫入這份共用 Excel 的功能，只要新增欄位，都要比照這個自我修復寫法**，不能只在 `default_header`（只有建立新分頁時才生效）裡加。

**機台代號欄位是 `<input list>` + `<datalist>` 自動完成，不是 `<select>` 下拉選單**——這是踩過雷才改的：一開始做成 `<select>`，新增/編輯機台前一定要 `await` 讀完生產日報表P5.3 的機台清單（`/api/batch_cost/machine_list`）才能開始編輯，結果內網環境偶爾連 Google 試算表逾時，整個編輯功能被卡住打不開。改成 `<datalist>` 之後，清單改成背景非阻塞載入（`ensureMachineList()` 絕對不能被 `await`），抓不到清單就退回普通文字輸入照樣能編輯，只是沒有自動完成建議而已——**之後這類「查詢清單輔助填欄位」的功能，一律用 `<datalist>` 這個模式，不要用 `<select>` 卡住編輯流程**。

**批成本明細頁的電費/油費是即時算出來的，不是直接讀 Excel 存的值**（`bcApplyUtilityCost()`，在 `bcLoadRecordsList()` 抓完資料後，對每筆記錄依它的「機台代號＋加工秒數＋完成數量」現場套用目前的『設備耗用設定』算一次，直接覆蓋寫回記錄物件）。這樣設計是因為這個功能上線前的舊記錄，Excel 裡本來就沒有電費/油費欄位，若只依賴存檔當下寫入的值，舊資料永遠是空的；即時計算則新舊資料一視同仁，且電價/設備參數異動後明細頁馬上反映最新設定，不用重新送出每一筆批成本計算。明細表的成本量級長條圖（`costCol`）也已經改成看「總成本(含刀具+油電)」而不是舊的「加工費用(含刀具成本)」。

實作慣例：
- **批成本計算/製令與刀具壽命分頁一律依「表頭欄名」動態對應寫入**（`app.py` 讀第一列表頭建 `name→col` map，照名稱寫入，不假設固定欄位順序），因為這兩個分頁的欄位順序會隨需求調整；新增欄位時只要 value_map 加對應 key 即可，不用管欄位實際排第幾欄。
- **建立日期優先採用 K1_P2 該筆的「出站時間」**（實際生產完成日期），查不到才退回今天日期——不是單純記錄送出當下的日期。
- 製令查詢：優先查 K1_P2（含已完工製令），查不到才備援查 SSRS 未完工製令報表；P2 的「製令」欄位本身帶序號尾碼（如 `-0010`），比對生產日報表P5.3 機台名稱/代號時需先去尾碼。
- 寫檔沿用既有 `try/except (PermissionError, OSError)` fallback 慣例（檔案被 Excel 開著時改存桌面並回傳 `warning` 訊息），見 `_save_batchcost_wb()`。
- 刀號輸入框支援省略 `T`（純數字 blur 時自動補上）與按 ↓ 鍵跳下一列，見 `bcNormalizeSlotStr`/`bcSlotInputKeydown`。

## 共用 Excel 範本的結構會持續變動

`BATCH_COST_FILE_PATH` 這份檔案是使用者日常自己用 Excel 維護的營運資料，不是程式專屬資料庫——分頁名稱、欄位順序、新增欄位都可能隨時被手動調整（這份功能剛開發出來時實際發生過：分頁從「刀具/刀表」兩頁變成「刀具資料/刀表/批成本計算/製令與刀具壽命」四頁）。因此：

- 上面「依表頭欄名動態對應」的寫法不是可選的最佳實踐，是**必須遵守的硬規則**，否則使用者調整一次分頁結構，程式就會寫錯欄位。
- 若不確定目前實際的分頁/欄位結構，不要相信這份文件或記憶裡的舊資訊，先 `cp` 一份本地副本實際讀表頭確認。
- **修改任何會寫入這份共用檔案的功能時，一律先用本地副本（例如 `_test_local_copy.xlsx`，暫時改 `config.BATCH_COST_FILE_PATH` 指向它）跑完整的讀寫測試，確認無誤後刪除測試檔，絕對不要直接對正式共用檔案做寫入測試**——這是公司其他人也在看的正式資料，不能拿來當測試垃圾桶。

## 開發背景

這個功能是單一次很長的對話、邊談需求邊開發出來的（沒有事先寫好完整規格），從查詢/計算/送出的核心流程開始，逐步加上批成本明細、刀表維護、刀具資料維護、統計圖表、各種容錯（製令免打 `-`、刀號免打 `T`、重複輸入警告、編輯刀表時可就地新增缺漏刀具）。之後若收到對這個功能的修改要求，預期是同一個漸進迭代的延續，沿用既有程式風格與已建立的設計語言（例如鏽橘色 `#A8431D` 代表「成本」相關數字，跟導覽列藍色系刻意分開）即可，不需要重新設計。
