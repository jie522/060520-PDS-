# CNC 程式管理

> 何時要讀這份文件：修改 `templates/cnc_program.html`、`/api/cnc_program/*`、或 `build_cnc_program_index.py` 時。

## 資料來源與實際資料夾結構

來源是一般網路資料夾（不是 PDM Vault），路徑設定在 `config.py`：
```python
CNC_PROGRAM_ROOT_PATH = r'\\192.168.1.99\加工部-資料夾\【技術資料】\P.程式'
CNC_PROGRAM_TEMPLATE_PATH = CNC_PROGRAM_ROOT_PATH + r'\【空白範本】'
```

實際結構**不完全一致**（人工長期累積出來的真實資料），有以下幾種混用模式：
- `FTB系列/[FTB210A夾管座]/250310.txt` —— 系列 → 品號 → 檔案（無機台分層）
- `FTB系列/[FTB400A側孔]/【綜銑01(協鴻)】/240227.txt` —— 系列 → 品號 → 機台 → 檔案
- `機台程式/【綜銑16(協鴻)A8】/20241119160505/O0011(...).txt` —— 機台 → 時間戳資料夾 → 檔案，無 `[品號]` 分層，品號代碼藏在檔名括號裡（約佔全部檔案 39%，這個分支的 `model` 欄位會是空白，但仍可靠檔名關鍵字搜到）
- `第6台程式/O0001.txt`、`PL032/[PL032圓桿]/...` —— 沒有「系列」這層，直接在根目錄

檔案幾乎都是 `.txt`（CNC G-code 純文字，ASCII 或含中文註解，讀取時 UTF-8 失敗會 fallback 解成 `cp950`），少量 `.jpg` 是治具/夾持照片。

`程式一覽表.xlsx`（根目錄下，861 列）是過去人工/工具產生的清單，**只到資料夾層級、不含個別檔案**，可能沒跟實際資料夾同步，沒有被本功能引用。

## 索引設計（build_cnc_program_index.py）

因為結構不一致，索引用**寬鬆規則**解析路徑，不依賴固定深度：
- 路徑中第一段 = `top_folder`（系列，或 `機台程式`/`第6台程式`/`PL032` 等無系列的根目錄）
- 路徑中第一個 `[...]` 包住的資料夾名 = `model`（品號，去括號）
- 路徑中（排除第一段）第一個 `【...】` 包住的資料夾名 = `machine`（機台，去括號）
- 檔名符合 `YYMMDD_說明.txt` 格式時解析出 `remark`（去掉結尾 `_[代號]` 標記）

掃描時**跳過**：`【空白範本】`（範本本身不算程式）、任何叫 `已刪除` 的資料夾（軟刪除的檔案要從索引消失，但實體檔案還在，可手動去資料夾找回）、`~$` 開頭的 Office 鎖定檔、副檔名不在 `{.txt,.jpg,.jpeg,.png,.bmp}` 的檔案（排除 `.xlsx`/`.zip` 等非程式檔）。

索引庫 `cnc_program_index.db` 放在 `app.py` 同目錄（跟 `zume_drawings.db` 同慣例，不是放 LOCALAPPDATA），靠 `sync_to_dist.py` 跟其他檔案一起同步到 `dist_embed`。

掃描全部約 25 個系列、1500+ 檔案，網路資料夾全掃約需 **3 分鐘**（`/api/cnc_program/rebuild` 的 subprocess timeout 設 600 秒），前端按「重建索引」時按鈕會顯示重建中、disable 避免重複點擊。

## 搜尋邏輯

`/api/cnc_program/search?q=...` 把整張索引表讀進記憶體（量不大，足夠快），對每一列組合 `top_folder+model+machine+filename+remark` 字串做關鍵字比對，語法跟主頁製令搜尋一致：空格 = AND，`-前綴` = NOT。結果上限 300 筆，超過會在表格最後一列提示筆數並要求縮小關鍵字。

## 寫入操作的安全處理

- **路徑跳脫防護**：所有帶 `relpath` 參數的操作（檢視/下載/刪除）都經過 `_cnc_safe_path()`，用 `os.path.normpath` 正規化後檢查仍在 `CNC_PROGRAM_ROOT_PATH` 底下，避免 `../../` 之類跳到資料夾外。
- **上傳檔名**：用 `_cnc_safe_filename()` 只移除路徑分隔符與 Windows 不允許字元，**保留中文**（不可用 Flask 內建的 `secure_filename`，那個會把中文整段砍掉）。
- **上傳防覆蓋**：目的地已有同名檔案就回 409 錯誤，要求使用者自己改檔名（通常加日期），不會靜默覆蓋既有程式檔。
- **刪除是軟刪除**：移到同層的 `已刪除` 子資料夾（檔名衝突時補時間戳），不是真的刪除；同時從索引表移除該筆，但不用整個重建索引。這是使用者明確要求的設計（生產用 CNC 程式檔誤刪風險高，所以不提供真刪除）。
- **新增範本**：`shutil.copytree(範本路徑, 新品號路徑)`，目的地若已存在會直接報錯擋掉，不會合併或覆蓋既有資料夾。

## 已知限制

- `機台程式/` 分支（約 39% 的檔案）因為沒有 `[品號]` 資料夾層，索引的 `model` 欄位是空的，畫面上「品號」那欄會顯示空白；但搜尋還是能透過檔名比對找到（品號代碼通常就寫在檔名括號裡，例如 `O0024(FTB210A-4PCS...).txt`）。
- 索引是離線快照，不會即時反映網路資料夾異動；上傳/刪除操作會立即同步更新索引（不用等重建），但別人直接在網路資料夾手動新增/刪除檔案不會自動反映，要按「重建索引」才會更新。
