# 客戶訂單查詢（製令詳細資訊「展開訂單」）

> 何時需要讀這份文件：改 `/api/order`、`/api/detail` 裡跟訂單有關的部分，或製令詳細資訊彈窗的「展開訂單」功能時。

2026-08-20 新增：製令詳細資訊彈窗（`index.html` `showDetail()`）如果這張製令有對應的客戶訂單，
會多顯示「訂單編號」徽章＋「展開訂單」按鈕，點開叫 `/api/order` 秀出訂單頭＋全部品項明細
（欄位對照 ERP 原生畫面「客戶訂單建立作業(COPI06)」的「資料瀏覽」分頁，逐欄實機核對過）。

## 資料表

- **`MOCTA`（製令主檔）** 的 `TA026`/`TA027` = 這張製令的來源訂單「訂單單別」/「訂單單號」
  （`TA028` = 訂單品項序號，對應 `COPTD.TD003`，目前沒用到）。不是每張製令都有——庫存單、
  半成品自製這類沒有客戶訂單來源的製令，這兩欄是空字串，`/api/detail` 這時 `result['order']`
  留 `None`，前端就不顯示「展開訂單」按鈕。
- **`COPTC`（訂單主檔，訂單頭，`TC001`+`TC002` 一張訂單一列）**：
  `TC004`=客戶代號、`TC053`=客戶名稱（英文全名，訂單上看到的就是這個，不是簡稱）、
  `TC003`=單據日期、`TC040`=確認者工號。
- **`COPTD`（訂單明細，`TD001`+`TD002`+`TD003` 一個品項一列）**：
  `TD003`=序號、`TD004`=品號、`TD005`=品名、`TD006`=規格（長文字）、`TD007`=庫別代號、
  `TD008`=訂單數量、`TD009`=已交數量、`TD013`=預交日。
- 庫別代號→名稱用 `CMSMC`（`MC001`/`MC002`），跟 `/api/inventory/future` 既有的庫別對照
  是同一張表，不是另外新猜的。
- 確認者工號→姓名嘗試用 `fetch_employee_name_map()`（Google 試算表『員工登錄系統』），
  這份名冊主要收錄加工課人員，業務/研發人員（例如訂單確認者）大機率查不到，
  查不到就直接顯示工號（不是錯誤，是預期行為）。

## 探測方式（供之後查其他訂單相關欄位參考）

`COPTC`/`COPTD` 這兩張表名不是憑記憶猜的，是唯讀 SQL 探測找出來的：先用一組已知的
訂單單別+單號（從 `MOCTA.TA026`/`TA027` 撈出、且使用者截圖驗證過的 ERP 原生畫面能對上），
掃過 `INFORMATION_SCHEMA.TABLES WHERE TABLE_NAME LIKE 'COP%'`，逐表找欄位命名慣例
`XX001`（單別）+`XX002`（單號）且 `WHERE XX001=? AND XX002=?` 撈得到列的表，
再把整列欄位值 dump 出來跟畫面截圖逐欄核對（客戶代號、單據日期、確認者、10 筆品項的
序號/品號/品名/規格/訂單數量/已交數量/預交日全部一字不差對上）才定案。
Computech ERP 沒有官方欄位字典，這套「先鎖定已知值、再掃表反推欄位」的方法比憑印象猜
`TC0xx`/`TD0xx` 代表什麼可靠得多，其他模組（客戶主檔、出貨單…）要查的話可以照搬。
